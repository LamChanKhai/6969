App1 — ユーザー管理API

メソッドエンドポイント説明認証
POST/gateway/user/新しいユーザーアカウントの作成不要
POST/auth/token/JWTアクセストークンの発行不要
POST/auth/refresh-token/JWTトークンの更新リフレッシュトークン
POST/gateway/user/find/条件ベースのユーザー検索（ページネーション付き）Bearerトークン
ユーザー登録フロー: POST /gateway/user/ → レスポンス(username文字列) → POST /auth/token/ → レスポンス({access, refresh})

App1 — ファイル・ヘルスAPI

メソッドエンドポイント説明認証
POST/gateway/transport/ZIPファイル検証とApp2への転送Bearerトークン
GET/gateway/health/App2モジュールの死活監視不要
ファイルアップロード

Headers: Authorization: Bearer <token>
Files: file=@sample.zip
期待レスポンス: "OK"

ヘルスチェック

パラメータ: module=/health.php
期待レスポンス: "OK"（プレーン文字列）
用途: モジュール別死活監視

App2 — ストレージAPI

メソッドエンドポイント説明
POST/storage.phpZIPファイル受領（id=ユーザーID、file=ファイル）、7z解凍、ストレージ配置（storage/<id>/）
GET/health.phpサービス死活確認
ファイル受領処理

パラメータ: id（ユーザーID）, file（ZIPファイル）
処理フロー: 受領 → 7z解凍 → storage/<id>/ へ配置

ストレージ構造

storage/
├── <user-1>/
  ├── extracted_file1.txt
  └── extracted_file2.png
└── <user-2>/
  └── ...

注意: App2はApp1からの内部通信のみ受け付けます。外部からの直接アクセスはできません。

API認証マトリクス

エンドポイント認証方式トークン必須
POST /gateway/user/—❌
POST /auth/token/—❌
POST /auth/refresh-token/リフレッシュトークン✅
POST /gateway/transport/Bearer アクセストークン✅
POST /gateway/user/find/Bearer アクセストークン✅
GET /gateway/health/—❌
セキュリティ設計: 機微な操作（ファイルアップロード、ユーザー検索）はJWTアクセストークンで保護されています。トークンなしまたは無効トークンでのアクセスは拒否されます。

APIレスポンス形式

ユーザー登録

POST /gateway/user/
Body: {username, email, password}
→ username文字列

トークン取得

POST /auth/token/
Body: {username, password}
→ {access, refresh}

ファイルアップロード

POST /gateway/transport/
Headers: Bearer <token>
→ "OK"

ヘルスチェック

GET /gateway/health/
module=/health.php
→ "OK"（プレーン文字列）

ユーザー検索

POST /gateway/user/find/
Body: {username: "xxx"}
→ ユーザーリスト

ストレージ

POST /storage.php
id=ユーザーID, file=ファイル
→ 解凍結果
