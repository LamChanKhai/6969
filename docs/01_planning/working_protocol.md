# ワーキングプロトコル — CSCV2025 プロジェクト

## 1. 基本ルール

### 1.1 読み込み順序

各ステップ開始時、必ず以下の順でドキュメントを読み込む：

1. `AGENTS.md`（プロジェクトルート）— ワークフロー全体のルール
2. `docs/00_converted/handoff_to_pm.md` — コンバーターからのノート
3. `docs/00_converted/` 内の全ファイル — RFPコンテンツ
4. 直前のステップの `handoff_to_*.md` — 前段階からのハンドオフノート
5. `docs/` 内の全ドキュメント — 既存の出力

### 1.2 出力ルール

- ドキュメント出力 → `docs/NN_*/` フォルダ（NNはステップ番号）
- コードデモ → `demo/backend/` または `demo/frontend/`
- スライド → `slides/`
- **AGENTS.md** はプロジェクトルートに配置（既に存在）

### 1.3 ファイル命名規則

| ドキュメント種別 | 命名規則 | 例 |
|-----------------|---------|-----|
| 計画書 | `project_plan.md` | `docs/01_planning/project_plan.md` |
| プロトコル | `working_protocol.md` | `docs/01_planning/working_protocol.md` |
| ハンドオフ | `handoff_to_[次ステップ].md` | `docs/01_planning/handoff_to_sa.md` |
| 設計書 | `architecture_design.md` | `docs/02_system_architecture/architecture_design.md` |
| 分析 | `[分析対象]_analysis.md` | `docs/02_system_architecture/security_analysis.md` |
| 提案書 | `proposal.md` | `docs/04_pm_final/proposal.md` |

## 2. ハンドオフプロトコル

### 2.1 ハンドオフノートの必須要素

各ステップ終了時に作成する `handoff_to_[次ステップ].md` には、以下の要素を含める：

```markdown
# Handoff to [次ステップ] — [今ステップ]

## ステータス
- [ ] 完了 / 部分的に完了 / 未完了

## 完了した作業
- [作業項目1]
- [作業項目2]

## 出力ファイル一覧
| ファイル | 説明 |
|---------|------|
| [ファイルパス] | [説明] |

## 注意事項
- [次のステップで注意すべき点]

## 未解決事項
- [保留中の課題]

## 次のステップのタスク
- [次ステップで実行すべきタスク]
```

## 3. ダイアグラム規則

### 3.1 Mermaid使用規則

- **Mermaid v11.12.2** 互換構文を使用
- 標準矢印: `-->`, `---`, `-.->`, `==>`
- 特殊文字を含むノードラベルは引用符で囲む: `A["Label (with parens)"]`
- 各 `subgraph` に `end` を必ず対応させる
- 予約語（`end`, `graph`, `style`）をノードIDとして直接使用しない
- 出力前にレンダリングを確認

### 3.2 ダイアグラム種別

| 種別 | 用途 | 推奨Mermaidタイプ |
|------|------|------------------|
| アーキテクチャ図 | システム全体構成 | `graph TD` |
| データフロー | データの流れ | `flowchart TD` |
| シーケンス図 | API呼び出し順序 | `sequenceDiagram` |
| ER図 | データモデル | `erDiagram` |
| ガントチャート | プロジェクトスケジュール | `gantt` |
| ステートマシン | 状態遷移 | `stateDiagram-v2` |

## 4. 品質基準

### 4.1 ドキュメント品質

| 項目 | 基準 |
|------|------|
| 言語 | 日本語（技術用語は英語併記可） |
| フォーマット | Markdown、一貫した見出しレベル |
| ダイアグラム | Mermaid使用、レンダリング確認済み |
| 表 | Markdown pipe table、適切にフォーマット |
| コードスニペット | 言語指定付きコードブロック |

### 4.2 セキュリティ分析基準

- OWASP Top 10 に基づく包括的なカバー
- 各脆弱性について：
  - 脆弱性の種類と説明
  - 影響範囲
  - 再現手順（可能であれば）
  - 緩和策
  - 優先度（高/中/低）

## 5. コミュニケーション

### 5.1 ツールの使用

| ツール | 使用タイミング |
|--------|---------------|
| **todo tool** | タスクリストの表示・更新（進行状況の追跡用） |
| **question tool** | 不明点の確認、意思決定の依頼 |

### 5.2 意思決定ログ

重要な意思決定は以下の形式で記録：

```markdown
## 意思決定ログ

| ID | 日付 | 決定事項 | 理由 | 決定者 |
|----|------|---------|------|--------|
| DD1 | YYYY-MM-DD | [決定内容] | [理由] | [役割] |
```

## 6. 完了条件

各ステップの完了条件：

- [ ] 全出力ドキュメントが正しいフォルダに保存
- [ ] `handoff_to_[次ステップ].md` が作成され、画面に表示
- [ ] 品質基準を満たしていること
- [ ] **STOP** — 次のステップに進まない

## 7. 緊急時対応

| 事象 | 対応 |
|------|------|
| 要件の不明点 | question tool で確認、仮定を明記 |
| 技術的制約 | 代替案を提示、決定を保留 |
| スケジュール遅延 | PMに報告、影響評価、緩和策の提案 |
| 品質問題 | 自己レビュー、修正、再確認 |
