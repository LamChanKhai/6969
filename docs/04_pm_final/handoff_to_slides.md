## 3. スライド作成指示

### 3.1 必須スライド構成

1. **タイトルスライド** — プロジェクト名、日付、プレゼンター
2. **プロジェクト概要** — 背景、目的、スコープ
3. **システムアーキテクチャ** — 2マイクロサービス構成図（App1ゲートウェイ + App2ストレージ）
4. **技術スタック** — Django/DRF/uWSGI、PHP/Apache、Docker Compose、SQLite3、JWT
5. **APIエンドポイント** — 主要API一覧と役割
6. **デモフロー** — ユーザージャーニー図（8ステップ）
7. **ワウモーメント** — 5つのハイライトポイント
8. **プロジェクトタイムライン** — 6フェーズスケジュールとマイルストーン
9. **チーム構成** — RACIマトリクス
10. **リスク管理** — トップリスクと軽減策
11. **成功基準** — 測定指標とターゲット
12. **Q&A**

### 3.2 構成図作成のヒント

- App1（Django/uWSGI:8000）とApp2（PHP/Apache）の2サービス構成
- Docker Composeネットワークを介した内部通信
- データフロー：クライアント→App1→App2→ストレージ
- 認証フロー：クライアント→App1（JWT発行）→トークン付きAPI呼び出し

### 3.3 デザイン指針

- シンプル、クリーン、プロフェッショナル
- 日本語表記（RFP要件）
- アーキテクチャ図はMermaidまたは手描き風ダイアグラム
- 各スライドに1つのメインメッセージ

## 4. 主要決定事項

| No. | 決定事項 | 根拠 |
|-----|---------|------|
| 1 | デモはローカルDocker Compose環境で実施 | 外部デプロイメントの複雑さを回避 |
| 2 | APIレベルでのデモに限定（UIなし） | スコープとリソースの最適化 |
| 3 | 既存コードベースの変更は行わない | デモの目的は設計検証、機能追加ではない |
| 4 | デモ期間は10営業日（2025-06-02〜2025-06-10） | 現実的なスケジュール、20%バッファ含む |
| 5 | 提案書・スコープは日本語で記述 | RFP要件 |
